# CS-250
CS-250 Module 8 Journal

1. How do I interpret user needs and implement them into a program? How does creating “user stories” help with this?

   User needs are best understood through active stakeholder engagement and listening carefully to how users describe their goals and the challenges they face.
   In the SNHU Travel project, this feedback was translated into user stories by using the format "As a user, I want (feature), so that (benefit)." These stories
   help to keep a team focused on real-world value and help to define clear acceptance criteria, guiding both the development and testing. For example, the
   user story about cruise preferences ensured the developer knew what behavior to build, and the tester knew exactly what to verify. This practice eliminates
   guesswork and centers development around the intent of the user.

2. How do I approach developing programs? What Agile processes do I hope to incorporate into my future development work?

   When I'm developing a program, I like to start by making sure I clearly understand what the user needs and what the program itself should do. Then, I like
   to break the work down into smaller, more manageable pieces so I can focus on one part at a time and test these pieces as I go. I also write out goals or
   steps before I begin coding so I have a clear direction. In my future development work, I want to continue using Agile practices that help me with
   organization and flexibility. For example, using user stories to describe what the program should do from the user's perspective helps me stay focused.
   I also want to incorporate the use of short development cycles (sprints) and keep reviewing my progress so I can adjust quickly if anything changes.
   Communicating early about updates or issues is another Agile habit I want to keep using whenever I begin to work with a team.

3. What does it mean to be a good team member in software development?

   To me, being a good team member means using clear communication, holding yourself accountable, and supporting the rest of the team so that we can all
   succeed together. This class helped me understand just how important it is to share updates, raise issues early, and respect everyone's role in the project.
   Through the use of Scrum events like the Daily Scrums, Sprint Planning, and Retrospectives, I saw how regular communication can keep a team on track and
   foster trust. During the SNHU Travel project, I learned that even a small delay or miscommunication can affect the whole team's progress. Whether I was
   acting as the developer, tester, or Scrum Master, I learned that listening, asking questions, and being flexible were just as important as completing
   my own tasks. The class as a whole showed me that software development is a team effort, and being reliable and open makes a huge difference. This is the
   type of software developer I want to strive to be.
